## 2. 原理与数据流

### 2.1 为什么是脉动阵列

矩阵乘法 Y=K·X 需要 64 个乘加（4×4×4）。脉动阵列用 16 个 PE 排成 4×4 网格，
**数据像血液一样在 PE 间按拍流动**（Kung & Leiserson，1978 [6]）：

- 每个 PE(k,i) 驻留权重 **K[i][k]**（行 i、列 k 的"转置"放置）
- 输入元素 X[k][·] 从第 **k 行左边界流入，每拍向右传一个 PE**
- 部分和从阵列顶部流入，**每拍向下传一个 PE**，沿途累加 `w×x`
- 第 i 列底部流出的就是结果行 y_{i,·}

每拍 16 个 PE 同时工作，无全局布线、只有相邻 PE 的局部连接——
这就是它成为 TPU 等 AI 芯片核心结构的原因 [7][8]。

### 2.2 PE 内部时序（手册给定表）

| 时钟 | x_in | p_in | p_out |
| ---- | ---- | ---- | ---- |
| 1 | x₁ | p₁ | 0 |
| 2 | x₂ | p₂ | p₁ + w·x₁ |
| 3 | x₃ | p₃ | p₂ + w·x₂ |

即 `p_out <= p_in + w·x_in`、`x_out <= x_in`，均寄存 1 拍。

### 2.3 完整时序推导（报告核心，可直接对照引用）

设 load 拉低后的拍号为 t（0 起）。以矩阵 m（注入窗口 t∈[4m, 4m+6]）为例：

**① 注入（对角错位）**：X[k][j] 必须在 **t = 4m + j + k** 拍出现在第 k 行左边界。
同行内 j 递增 1 拍一个（行节奏），行间 k 递增再错 1 拍（列对齐）——
因为 X[k][j] 每向右过一个 PE 晚 1 拍、每向下过一个 PE 的部分和也晚 1 拍，
错位 j+k 才能保证**在第 i 列恰好与 K[i][k] 相遇**。

**② 阵列内传播**：X[k][j] 到达 PE(k,i) 的拍为 `4m + j + k + i`；
该拍该 PE 累加 K[i][k]·X[k][j] 进部分和。

**③ 列底出现**：部分和再向下 (4−k) 个 PE（各 1 拍），
`y_ij` 在 **t = 4m + i + j + 4** 拍出现于第 i 列底部。

**④ 输出对齐**：y_ij 出现时刻 i+j+4 各不相同（4m+4 到 4m+10），
对 y_ij 施加深度 **6−i−j** 的延迟后，16 个结果在 **t = 4m + 10** 拍**整组对齐**，
统一锁存进 `res`。这就是输出"拍齐"设计的由来。

**⑤ 连续流水**：矩阵 m+1 从 t=4m+4 拍开始注入（窗口重叠），
每 4 拍注入一个矩阵、每 4 拍产出一个结果矩阵：

- **启动间隔 II = 4 拍**（每 4 拍一个矩阵），达手册理论峰值
- **单矩阵延迟 = 10 拍**（首个元素注入到整组结果锁存）
- **稳态吞吐 = 16 MAC/拍**（64 MAC / 4 拍），16 个 PE 全部满载

**⑥ 换权重**：load=1 装入新权重的同时**清空全部流水寄存器**，
旧计算作废。手册明确警告：若不清除旧部分和，新权重会叠加错误结果。
代价：重新灌注需 10 拍延迟——连续换权重场景吞吐会显著下降。

## 3. 接口与数据约定（设计规格）

参考实现的总线编码约定（[lab_3_reuse/rtl/MULT.v](../../lab_3_reuse/rtl/MULT.v) 头部注释为权威描述）：

| 总线 | 位段 | 含义 |
| ---- | ---- | ---- |
| `weight[127:0]` | `[8*(4i+k) +: 8]` | 权重 K[i][k]，**行主序**，load=1 时 16 个 PE 并行装入 |
| `input_data[127:0]` | `[8*(4q+k) +: 8]` | 帧槽位 (4q+k)：第 t=4f+q 拍第 k 行左边界的输入 |
| `res[303:0]` | `[19*(4i+j) +: 19]` | 结果 y_ij，**行主序**，t=4m+10 整组锁存 |

**输入按"帧"驱动**：一帧 4 拍喂完 16 个槽位。帧 f 槽位 (4q+k) 的内容按 2.3① 反推：
`t = 4f+q` 拍第 k 行需要 `X_m[k][j]`，其中 `4m+j = 4f+q−k`（越界填 0）。
tb 中的 `pack_frame` 任务就是这个映射的参考实现——**驱动逻辑放在 tb/上游，阵列本身保持简单**，
这是与手册"设计文档规定数据总线编码、装入顺序和启动拍号"要求相对应的一种合理设计决策。

## 4. 参考实现（双版本）

| | 复用版 [lab_3_reuse](../../lab_3_reuse/) | 独立版 [lab_3_standalone](../../lab_3_standalone/) |
| ---- | ---- | ---- |
| PE 乘加 | **结构实例化** Lab2 `MULT8_WALLACE` + Lab1 `ADDER` | 行为级 `p_in + w_hold * x_in` |
| 依赖 | lab_1、lab_2 | 自包含 |
| 适用 | 体现课程连贯路径；已完成实验一二 | 只做实验三 |
| 接口/时序/tb | **完全一致** | **完全一致** |

顶层 `MULT` 的结构（两版相同）：

```
节拍计数(phase/t_run) → 4×4 PE 阵列(generate) → 行输入帧选择 →
列底输出 → 对齐延迟链(深度6−i−j) → capture_en 整组锁存 res
```

PE 内部（复用版）：`w_hold`（权重寄存器）+ `MULT8_WALLACE`(w×x) + `ADDER`(p_in+积) + `x_out/p_out` 寄存器。
流水寄存器把关键路径限制在**单个 PE 的乘加**内，与阵列规模解耦——全流水阵列的频率基础。

## 6. 综合结果与解读

```bash
cd lab_3_reuse/syn（或 lab_3_standalone/syn） && yosys synth.ys
```

| 版本 | cells | 最长拓扑路径 | 说明 |
| ---- | ---- | ---- | ---- |
| 复用版 | 8547 | **37 级** | = 单 PE 内"Wallace 乘法 + Kogge–Stone 加法"路径 |
| 独立版 | 7709 | **38 级** | ABC 对行为级 `*`/`+` 自由重构，面积略省 |

解读（报告第 ③ 项素材）：

1. **频率**：关键路径 ≈ 单个 8 位乘加，与 4×4 规模无关——阵列扩大到 16×16，
  理论关键路径几乎不变（仅扇出/布线压力增加），这就是脉动阵列的可扩展性
2. **吞吐/延迟**：II=4 拍、延迟 10 拍（2.3⑤）；峰值算力 16 MAC/拍
3. **面积**：约 1200 个触发器（16 PE × 35 bit + 对齐链 + res），
  流水寄存器占相当比例——全流水的面积代价
4. 两版 3% 的面积差说明：行为级写法把优化自由度让给综合器，
  结构级写法把微架构控制权留在设计者手里——各有千秋

- 优化设计（写出自己的思考，示例方向）：

**演示准备**：

1. 准备一组能口算验证的矩阵（如单位阵、全 1、对角阵），现场讲清每拍数据位置

3. 吞吐率问题：II=4、每拍 16 MAC；**换权重代价**：load 期间流水清空，
  连续换权重的有效吞吐 = 64 MAC / (10+n) 拍量级——宜定量说明
4. 优化方向见上，挑 1-2 个讲清动机与代价

## 8. 常见问题

| 问题 | 原因/解决 |
| ---- | ---- |
| 换权重后结果混入旧值 | load 时未清空流水寄存器（手册明确警告的坑，tb 场景 3 专门抓这个） |
| 结果整体错位/串行 | 注入没按 j+k 对角错位；检查帧打包映射 `4m+j = 4f+q−k` |
| 编译报 `input` 相关错误 | `input` 是关键字，端口改名 `input_data` |
| 首组结果对、后续全错 | `phase/t_run` 没在 load 时清零，或捕获条件写错 |
| 结果全是 X | 复位时序：rst_n 先拉低 ≥2 拍再释放；检查寄存器是否都有复位分支 |
| 输出永远不更新 | 捕获门控 `t_run` 饱和值/相位条件与理论拍号对不上（先算 2.3④ 再编码） |
| `Unknown module` | 复用版编译漏带 lab_1/lab_2 的共享源文件（见第 5 节命令） |
